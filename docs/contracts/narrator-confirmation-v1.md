# Narrator contract v1: confirmation from the narrator side

Answers the four open questions of [narrator-request-v1.md](narrator-request-v1.md) for the implementation in `mcp-service/` (author: Anshu Jadhav). The request and response shapes are accepted **unchanged**.

| # | Question | Answer |
|---|---|---|
| 1 | MCP client revision and transport | The narrator is an MCP client speaking spec revision **2025-06-18** (the server also accepts 2025-03-26 and 2024-11-05). Transport to its MCP server: **stdio** child process by default, or **Streamable HTTP** (request/response, bearer token) when `NARRATOR_MCP_URL` is set. Between the platform and the narrator the transport is plain HTTPS/HTTP POST as in the contract. |
| 2 | Is a static bearer token acceptable | Yes. The narrator checks `Authorization: Bearer <NARRATOR_BEARER_TOKEN>` with a constant-time comparison; set the platform's `NARRATOR_TOKEN` to the same value. Without a configured token the service accepts anyone and prints a warning (local demo only). |
| 3 | Real payload limits | Request body up to **64 KB** (HTTP 413 above it), `question` up to 2000 characters, reply text cut to **4000** characters, all string fields in the request capped at 400 characters after sanitising. Per-call deadline 18 s (under the platform's 20 s). Tool results to the model are capped at 48 KB each. |
| 4 | How it is hosted | A single process (`python -m datamend_mcp narrator`, or `Dockerfile.mcp`) with no database. On a sleeping free tier the first request can exceed the platform's 20 s timeout, in which case the platform stores nothing (as the contract says). |

Behaviour the platform will see:

* `200` with `{text, contributions, model_id, confidence}`. `contributions` is `[{check, note}]` taken from the evidence the platform sent (not generated by a model). `confidence` is always `null`: the narrator computes none.
* `model_id` is `datamend-mcp-grounded-v1` (no language model configured) or `datamend-mcp-narrator/<model>` (LLM mode).
* `400` malformed request; `401` bad token; `413` too large; `429` over 60 requests a minute; `501` a chat question this mode cannot answer honestly (grounded mode only); `502` the language model or the MCP server failed or ran out of time. Any non-200 makes the platform store nothing and tell the user the narrator did not answer.

Status: confirmed by the implementer of the narrator; **not yet exercised against the real platform** (see `docs/mcp/ANSHU_BRANCH_DOCUMENTATION.md`, section 7).
